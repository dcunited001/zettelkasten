*** 1: How does V8's Reactor Pattern schedule and manage JS evaluation?
:PROPERTIES:
:CUSTOM_ID: how-does-v8s-reactor-pattern-schedule-and-manage-js-evaluation
:END:
Javascript is almost entirely single-threaded, but chromium uses IPC and
OS processes for concurrency. How are chunks of bytecode for /mostly
"synchronous"/ bytecode scheduled for execution?

Does the V8 engine use the "Reactor Pattern" almost exclusively to
manage threads for concurrent "async" requests? Or does the V8 engine
have sophisticated workload prioritization for small chunks of bytecode
submitted for evaluation by disparate event handlers across a tab's web
application and extensions?

*** 2: Is everything in JS essentially asynchronous?
:PROPERTIES:
:CUSTOM_ID: is-everything-in-js-essentially-asynchronous
:END:
Since the far majority of code scheduled for evaluation is contained
within async promises, is there any meaningfully synchronous evaluation?
Without a loop or a timer or moar promises, how can a user's JS program
guarantee that JS statements execute in logical sequence?

1) manages threads of execution
2) and enforces internal consistency for data the V8 "virtual machine"
   operates on
3) especially as it pauses & unpauses execution of =async= handlers
   competing for evaluation.

async, isn't /everything/ essentially running asynchronously? Since
