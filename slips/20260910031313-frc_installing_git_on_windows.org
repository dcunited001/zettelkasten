** Git and Github Setup

This outline accompanies the =git= tutorial video from Sept. 2026. There are some
technical details, but the intent here is to cover:

+ How these GUI applications are configured in Windows.
+ How you can use the GUI features to learn =git= concepts
+ And to introduce some of those =git= concepts.

If you do want to =git ahead= (punn intended), then walk through the exercises at
[[https://learngitbranching.js.org/?locale=en_US][learngitbranching.js.org]]. This is not required, but will help a ton if you want
to learn these skills faster.

*** Git Credential Manager (GCM)

GCM and =gh= store login info separately. You will need to logout twice...

+ [ ] *Login to Github for git commands with:* =git credential-manager github login=
  - test =gh= command before, test =gh= command after
+ [ ] Ensure ~Github Desktop~ uses =git-credential-manager=
  - =File > Options > Advanced=. Then click =Use Git Credential Manager=

*** Optional: =gh= CLI Tool

=gh= makes it easier to stay updated on issues and pull requests.

+ Run =gh auth login=, select your preferred protocol and account options.
+ Run =gh auth setup-git= so =git= uses your =gh= authorization for CLI.

*** Sourcetree

+ [ ] *Staging files:* =git add $filename=.
+ [ ] *Branching:* we'll use a =main= branch and a =dev= branch.

=git pull= will check the upstream for the branch your on. David can set up how
your local branches track the remote branches. This should be simple because we
won't use feature branches. Only =main= and =dev=.

+ *Check what a local branch is tracking:* =cat .git/config= and look for =[branch
  "name"]=
+ [ ] *How to fetch & pull:* =git fetch origin= and =git pull=
  - =git fetch= checks for remote changes, but doesn't affect your local copies.
  - You'll see what gets fetched in Sourcetree.

*To avoid losing work:* create a throwaway branch before =git pull=, just in case.
This is optional: with the configs below, lost work wouldn't happen often.
Instead, you'll get a merge conflict _during a rebase_. This means you can always
=git rebase --abort= which rewinds your branch to before the =git pull=.

+ [ ] *Create a local branch:* =git checkout -b $branch= or =git switch $branch= (newer)
+ [ ] *How to commit:* =git commit -m 'type/topic: 7-word summary'=
+ [ ] *How to push:* =git push origin dev=. If you can't push, send me a message on
  Band. Early on, I will manage pushing code up.

*Optional:* read over the [[https://www.conventionalcommits.org/en/v1.0.0/#summary][Summary for "Conventional Commits"]]. We won't use it, but
it's just simpler to develop these habits earlier on. The reason the first line
should be =< 50= characters is because more advanced users want =git log= to format
properly in a terminal.

*** Git Configs

Configuration is in =%USERPROFILE%=

#+LATEX: \taburowcolors[2]2{lightgray..white}
#+ATTR_LATEX: :environment tabu :center nil :placement [h!] :align |r|l|l|l|
|------------+---------+--------------------------+--------------------------------------------------|
| File       | Scope   | Path                     | Description                                      |
|------------+---------+--------------------------+--------------------------------------------------|
| Git Config | Global  | =%USERPROFILE%\.gitconfig= | Your own default =git= settings                    |
|            | Project | =.git/config=              | The project's config gets merged on top          |
| Git Ignore | Global  | =%USERPROFILE%\.gitignore= | By default, =git= always ignores these files.      |
|            | Project | .gitignore               | Can be in any project directory! (helpful later) |
|------------+---------+--------------------------+--------------------------------------------------|
Checking configs:

+ Open =Git Bash=. Run =ls -l .gitconfig=, then =cat .gitconfig= to view it.
+ Run =git config list --global= to check out =git= sees it
+ Run =git config list= in a project to see what =git= sees there.
