*** Ingest HDF5 -> Load Buffers For RLX -> Compute Output -> Visualize

Working to ingest HDF5 for any application is complicated.

+ The format's design was basically specified by mad-scientists in the 1970's
  (1990's is probably more accurate, since NetCDF has had several revisions.)
  - These are like your NASA/NOAA/YAPA folks (yet-another-particle-accelerator)
    and they're crazy
+ The main point: HDF5-producing applications consume complicated data at,
  potentially, LHC speeds,
  - intermediate applications & networking are required to transform it to the
    endpoint actually producing HDF5 or producing the last grouping/aggregation
    that gets converted to HDF5
  - Not only is it a "read-fast" format, it's also a "write-fast" format
  - and it's not just "write real super-fast" it's like "write from these memory
    addresses with =memcpy= from complicated, proprietary/bespoke scientific
    instrumentation fast"

So, there's that. But as consequences of that:

+ Code in ETL stages must reference specific keys/structure in HDF5
+ Quick transforms before loading RTX buffers probably references keys/structure
  which would change if HDF5 format changed
+ Then the actual relationships/dimensionality of tensors also depends on the
  ingested HDF5(s)
+ Then it produces complicated output which needs to be visualized. Guess what?
  That also changes when you make arbitrary changes to your input format.

So that's like 4+ places where a change in one place ripples a "naming problem"
throughout the rest of your code. It's all fun & games until hitting =F5= in
VSCode (lol) costs $10,000.

Changed formatting not a problem when you have no design control over the format
(someone far above your paygrade made those decisions and they may have
literally landed robots on space-things) but...

+ if the format needs to specify arbitrary mesh/face/vertex buffer attribute
  layouts for esoteric geometry... well now it is your problem, isn't it?
+ Who are you going to call for support? Ghostbusters? It's not like you have a
  rolodex of MIT scientists to ask for advice.

Anyways, so asking "Claude" to assemble this shit is probably a huge mistake --
agents require evaluation loops or tooling for mocks, which can't catch
everything.
