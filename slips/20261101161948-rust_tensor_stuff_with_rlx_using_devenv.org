**** Matching =rustc= to ROCm's =llvm=, =clang= and =linker-plugin-lto=

+ Check =$ROCM_PATH/llvm/bin --version=, which is =22.0.0=
+ Compare =/nix/store/...-devenv-rust-linker-clang --version=, which is =21.1.8=

Need to ensure that =rust= uses the =LLVM= that ships with =/opt/rocm= (the
symlinkJoin profile is effectively the same as that)

+ The instant =OPENBLAS_LIB_DIR= gets set/exported, builds start failing.
  - the compiler infrastructure =cargo= funnels through avoids "mixxing rocm's
   hip stuff in" ... in some way.
  - AFAIK it still uses ROCm's APIs to direct CUDA kernels to the GPU. So =cargo
    run -p rlx-bench --example bench_all --features rocm= still works, unless
    setting =OPENBLAS_LIB_DIR= bc at that point, the compilation gets all
    "hipify'd"
  - It even fails without =--features rocm=, since I'm setting =OPENBLAS_LIB_DIR= to
    path containing =.so= libs for BLAS that expect to use =hipCC=, etc
+ [[https://github.com/meillaya/kernscope/blob/1c69ae251e3c22c3189d8a2e04cc5b15ea8624c6/devenv.nix][meillaya/kernscope devnix.nix]] mixes CUDA, ROCm and hipcc ... but it doesn't
  need to go through =cargo=, =rustc=, etc
