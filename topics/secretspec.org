** Git Credential Manager

See [[https://github.com/cli/cli/issues/3796][cli/cli#3796]] and [[https://secretspec.dev/integrations/git/#use-a-custom-manifest][use-a-custom-manifest]]. 

#+begin_src shell
provs=(age age123 pass sops gopass)
manifest="$HOME/.dotfiles/secretspec.toml"
secretspec git configure --global -f "$manifest" \
    --url https://github.com --username="$EMAIL" --provider=$provs # not email...

# --token-secret...
#+end_src

Adds an =[include]= to =~/.gitconfig= when global.

+ Uses a [[https://github.com/cachix/secretspec/blob/77728d99798a4881aa4aedebb0437d8b40462921/secretspec/src/integration/git.rs#L38][bundled manifest]] unless =-f= is specified.
+ =null= provider should always fail
+ Instead of that, use =--provider=ageykpiv= that doesn't require a URI
  - i.e. =keyring= or other IPC-based providers
  - otherwise requires a =secretspec.toml= somewhere. see [[https://secretspec.dev/integrations/git/#use-a-custom-manifest][custom manifest]]
+ pass://path/{profile}/{key}?store_dir=. :: does not seem to accept relative
  paths (to =config-toml= or any relative paths)
  - prepending =.= to the pass URI is chaotic good

Defaults to =dotenv= provider or whatever's set to =defaults.providers= in your
=config.toml=. hmmmm ... i assumed i don't care about =.env= files bc i will usually
have explicit configuration of =secretspec.toml= per-project (thuse requiring
