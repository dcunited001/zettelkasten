#+begin_src nix
{
  process.proxy.enable = true;

  processes.web = {
    exec = "${pkgs.python3}/bin/python -m http.server $PORT";
    ports.http.allocate = 8000;
    env.PORT = builtins.toString config.processes.web.ports.http.value;
  };
  processes.web.proxy.https.enable = true;
  processes.web.proxy.hostname = "app.localhost";
  processes.web.ports.http.proxy.hostname = "public.localhost";
  processes.web.ports.admin.proxy.hostname = "control.localhost";

  processes.web2 = {
    exec = "caddy run";
    linux.capabilities = [ "net_bind_service" ];
  };
}
#+end_src

From changelog

#+begin_quote
2026-08-24: =mkcert= no longer fails when the local CA cannot be trusted

=mkcert -install= needs sudo and, on darwin, security to add the local CA to the
system trust stores.

Those tools are unavailable on machines without a system PATH or without a way
to gain privileges, such as CI runners. =devenv= now prints a warning instead of
failing when the local CA cannot be trusted. The certificates are generated in
either case, and =env.CAROOT= and =env.NODE_EXTRA_CA_CERTS= point at the local CA.

devenv also adds the system directories to the PATH of the mkcert calls, so the
tools are found when they exist.

+ /usr/bin, /bin, /usr/sbin, /sbin on darwin
+ /run/wrappers/bin on NixOS
#+end_quote

**** Profile Linking

From the changelog (since it seems important for later)

#+begin_quote
=$DEVENV_PROFILE= used to link every output of each package in packages, including
doc, debug and static outputs, and outputs that collide with each other, such as
the individual certificate files of pkgs.cacert.

=$DEVENV_PROFILE= links outputs in the package's =meta.outputsToInstall= (what =nix
profile= install would pick) plus the =out=, =bin=, =lib=, =dev= and =include= outputs the
shell already exposes. Selecting an output explicitly, such as =pkgs.sqlite.dev=,
links only that output.

If you relied on another output being in the profile, add it to packages
explicitly, for example =pkgs.openssl.doc=.
#+end_quote
